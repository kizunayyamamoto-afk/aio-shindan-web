AIO診断ツール

ページのHTMLソースを貼り付けると、AI検索に拾われやすくするための改善点を優先度順に出します。1回に診断できるのは1ページです。処理はこのページ内だけで行い、外部には送信しません。

使い方（はじめにお読みください）

このツールは、Webページが「AI検索に読み取られやすいか」を調べて、直す点を教えます。難しい設定は要りません。次の順番で使ってください。

  1. ページのソースをコピーする調べたいページをブラウザで開き、Ctrl+U（Macは Cmd+Option+U）を押します。新しいタブに文字がたくさん出るので、Ctrl+A（全部を選ぶ）、Ctrl+C（コピー）の順に押します。
  2. 下の「1. ソースを入れる」に貼って、「診断する」を押す入力欄をクリックして、Ctrl+V（貼り付け）。会社概要や店舗情報のページなら、「会社概要／店舗情報の正本ページ」にチェックを入れてから押します。
  3. 結果を見る点数と、直す点の一覧が出ます。高（赤）は急ぎ、中（黄）、低（青）の順です。【A】はそのまま直せるもの、【B】はお客様に確認が必要なものです。各項目の「なぜ必要か・直し方の手順」に、やさしい手順が書いてあります。
  4. 直したら、チェックを付ける直した項目は、「修正が完了した」にチェックを入れます。「修正一覧をコピー」を押すと、ノートやチケットにそのまま貼れる文ができます。
  5. 直ったか確認する直したページのソースを、もう一度コピーします。「3. 修正後のソース」に貼って、「直っているか確認する」を押すと、直った項目と、まだ残っている項目が分かります。
  6. 表示速度を比べる（必要なとき）「4. 表示速度」で、修正の前と後の速さを記録して、比べられます。
こんなときは
  • ログインが必要なページは？　ログイン後の画面ではなく、だれでも見られる公開の画面のソースを使ってください。
  • 貼り付けた内容は、どこかに送られますか？　いいえ。お使いのブラウザの中だけで調べます。外部には送られません。
  • 記録（チェックや速度）はどこに残りますか？　お使いのブラウザの中だけです。ほかの人や、別のパソコンには、共有されません。
  • 全ページを調べるには？　1回に調べられるのは1ページです。ページごとに、同じ手順で調べてください。
  • 数字が合わない、おかしいと思ったら？　ページ下の「意見」の欄から、内容を送ってください。

1. ソースを入れる

いま入っているのは動作確認用の架空のサンプルです。実際のページのソースに置き換えてください。

URLを入れると、ページごとに「修正が完了した」のチェックを覚えます。「診断する」を押すと、この修正前のソースがこのブラウザに保存され、あとで修正後のソースと比べられます。

KIZUNA AIO設定値と突き合わせる（任意）

設定画面は見るだけで、値を書き換えることはありません。ここに写した値が本文とJSON-LDに出ているかを調べます。

3. 修正後のソースで、直っているか確認する

修正したページのソースを、もう一度貼り付けてください。上の「診断する」で保存した修正前のソースと比べて、直った項目・まだ残っている項目・新しく出た項目を表示します。直っていた項目は、上の結果で自動的にチェックが付きます。設定値の入力欄は、いまの入力内容で診断します。

4. 表示速度を測って、修正の前後で比べる

このツールは、外部のサイトの速度を自動では測れません。Google の「PageSpeed Insights」で測った数字を、ここに記録して比べます。記録はこのブラウザの中だけに残り、ほかの人には共有されません。

  1. 下にURLを入れて、「モバイルで測る」を押す（PageSpeed Insights が新しいタブで開く）。結果が出たら、点数・FCP・LCP・TBT・CLS・Speed Index の数字を読む。
  2. 区分を「修正前」にして、数字を入れて「この測定を記録」を押す。同じページを3回測って、3回とも記録すると、ばらつきの影響が小さくなる。
  3. 修正する。1回の修正は1つだけにする。同じ条件で、また3回測って、区分を「修正後」にして記録する。
  4. 下の「修正前と修正後の比べ方」に、結果が出る。悪くなった項目があれば、その修正だけを元に戻して確かめる。

記録した測定

修正前と修正後の比べ方

数字の意味と目安
  • 点数　全体の点数です。90以上が良い、50未満が悪いとされています。
  • FCP　画面に最初の文字や画像が出るまでの時間です。1.8秒以内が良い、3秒より長いと悪いとされています。
  • LCP　ページの一番大きな部分が出るまでの時間です。2.5秒以内が良い、4秒より長いと悪いとされています。
  • TBT　画面は出たのに、操作できずに待たされる時間です。200ミリ秒以内が良い、600ミリ秒より長いと悪いとされています。
  • CLS　読み込み中に画面がずれる大きさです。0.1以下が良い、0.25より大きいと悪いとされています。
  • Speed Index　画面が出ていく速さです。3.4秒以内が良い、5.8秒より長いと悪いとされています。
  • 測るたびに数字は変わります。比べるときは、同じURL、同じ「モバイル／パソコン」、できれば同じ時間帯で測ってください。
  • 変化が5%以内（点数は3点以内、CLSは0.02以内）は、誤差の範囲として「ほぼ同じ」と表示します。
